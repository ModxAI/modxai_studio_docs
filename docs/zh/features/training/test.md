## 使用前准备

- 已安装具备训练能力的[运行环境](../settings/environment.md)。
- 有已经结束的训练任务和可用的检查点。列表可选择已完成、已停止、失败或错误状态的任务，但有任务记录不代表一定有可加载的检查点。
- 保留完整模型及分词器文件。测试未合并的 LoRA 检查点时，还需要原始基础模型目录。
- 为模型加载预留足够内存或显存。

## 测试流程

1. 打开「自我改进 → 训练 → 测试」，选择训练任务。
2. 选择检查点。LoRA 任务还会显示基础模型路径，检查它是否仍指向正确目录；必要时选择基础模型目录中的文件来更新路径。非 LoRA 任务直接使用所选检查点。
3. 点击「推理参数配置」，设置生成参数和可选系统提示词，点击「应用」。
4. 点击「开始」，等待环境检查和模型加载完成。页面切换为「交互式测试」，显示日志和输入框。
5. 输入一个测试问题，按 Enter 或点击「发送」，在日志中查看问题及回答。等待本次回答完成，再发送下一个问题。
6. 测试结束后点击「退出」。需要换检查点或修改参数时，先退出，再重新配置和开始。

**每次输入独立生成回答，不会把之前的问题和回答作为上下文继续发送。** 日志里出现连续问答，不代表支持带上下文的多轮对话。需要前文信息时，在当前问题中一并提供。

## 推理参数

### 基础参数

| 参数 | 默认值 | 用途与限制 |
|------|--------|------------|
| 温度 | 0.7 | 调整采样随机性；建议先保留默认值，再小幅调整 |
| 最大长度 | 256 | 本次回答最多生成的 token 数，界面可调范围为 1–8192；不是输入与输出总长度 |
| Top P | 0.9 | 按累计概率筛选候选 token |
| Top K | 50 | 限定概率最高的候选 token 数；`0` 不使用此限制 |
| 重复惩罚 | 1.1 | 抑制已出现 token 的重复；`1` 不加惩罚，避免设为 `0` |
| 存在惩罚 | 1.1 | 界面保留此项，但当前交互测试中不影响生成结果 |
| Min P | 0 | 按相对于最高概率 token 的阈值筛选候选；`0` 不启用 |
| 随机种子 | 42 | 用于重复测试；`0` 不固定种子。相同种子不保证跨设备、环境的输出完全一致 |

token 是模型处理文字的单位，不等于字符数。增大最大长度会增加生成时间，也可能增加内存需求。模型自身的上下文容量仍有限制。

### 高级参数

- **启用思维链**：默认关闭，只在模型及其对话模板支持时有效，不能使普通模型自动获得这项能力。
- **系统提示词**：设置模型的角色或回答要求，最多 `4000` 字符。例如「用简短中文回答，并在不确定时明确说明」。

参数在启动测试时生效，运行中不能直接切换。若要比较参数，退出测试后修改并重新开始。

## 测试建议

- 准备一组固定问题，覆盖常见任务、未见过的问法、格式要求和超出知识范围的问题。
- 比较检查点时，保持问题、系统提示词和生成参数一致，记录每次使用的检查点。
- 逐个改变参数，避免同时修改多项后无法判断影响。
- 人工检查事实、格式和遗漏，不要仅凭回答流畅或基准分数较高就认定模型可靠。

## 常见问题

### 没有可选任务或检查点

先确认训练已结束，并实际保存了检查点。检查点文件被移动、删除或不完整时，任务记录仍可能存在。

### 回答不完整

检查「最大长度」是否太小。适当增加后重新测试；模型也可能主动结束回答。开启思维链时，还要为思考及最终回答预留生成长度。

### 回答重复或偏离主题

先用同一问题和默认参数复测，再逐项调整温度或重复惩罚。同时检查训练数据质量和系统提示词。当前存在惩罚不会改变测试结果。

### 后续问题没有沿用前文

这是独立问题测试。请把必要的背景写入当前问题，不要只发送依赖前文的代词或追问。

### 加载失败

确认检查点、基础模型及分词器路径仍然有效，并释放其他程序占用的内存或显存。测试失败后可保留日志查看原因，点击「关闭」返回配置页面，再处理错误并重试。
