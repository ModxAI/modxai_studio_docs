## 使用前准备

- 在[设置 → 系统](../settings/environment.md)中安装具备训练能力的环境。
- 准备完整的本地模型目录，包含模型配置、权重和可用的分词器文件。使用可训练的 Hugging Face 格式模型，不能选择 GGUF 文件。权重可以是模型支持的 Safetensors 或 PyTorch 格式，不要求文件统一叫 `model.safetensors`。
- 准备与训练类型、模型分词器匹配的训练文件，见[数据配置参数](#数据配置参数)。需要训练中评估时，另备评估文件。
- 准备可写的输出目录，为检查点预留磁盘空间。训练会持续占用内存或显存。

训练设备支持 CPU 和 NVIDIA CUDA。「自动检测」优先使用可用的 CUDA，否则使用 CPU；选择 GPU 也应确认实际运行环境具备 CUDA。这里的训练设备选项不代表其他推理后端均可用于训练。

| 区域 | 用途 |
|------|------|
| 基础配置 | 任务名称、参数模板、训练类型、训练设备、任务管理 |

## 训练流程

### 创建新任务

1. 打开「自我改进 → 训练 → 准备」，在「任务管理」中选择「新任务」。
2. 保留自动生成的任务名称，或输入便于识别的名称。
3. 选择训练类型、对应的参数模板和训练设备。训练类型包括 SFT 和预训练，不包含 DPO。
4. 点击「训练参数配置」，填写训练数据文件、训练模型目录和训练输出目录。模型路径旁的文件按钮用于选择模型目录内的文件，选中后填写的是其所在目录。
5. 按需要调整参数，点击抽屉底部「应用」。首次尝试可从模板参数开始，先用少量数据检查流程。
6. 点击「开始」。若提示参数、文件或环境问题，处理提示中的问题后重试。
7. 任务启动后会自动切到[监控](./monitor.md)。确认任务显示「运行中」，并出现训练日志和指标。

任务显示「已完成」表示本次训练结束。模型是否满足你的要求，还需通过[评估](./evaluate.md)和[测试](./test.md)确认。

### 继续已有任务

在「任务管理」选择已有任务，检查加载的参数，必要时修改并应用，然后点击「开始」。**选择已有任务不等于从上次进度续训**；需要续训时，必须配置下面的检查点路径。

### 断点续训

1. 在「训练参数配置 → 数据配置」的可选参数中填写「恢复训练检查点路径」。
2. 选择与原模型和训练配置匹配、包含完整训练状态的检查点目录。只有最终模型权重或 LoRA 权重，不一定足以恢复训练进度。
3. 检查输出目录和其他参数，点击「应用」，再点击「开始」。通过日志确认实际恢复的检查点和步数。

### 环境检查

点击「开始」后会检查训练能力及必要文件。检查通过不代表内存、显存或模型兼容性一定满足要求，仍需查看启动日志。

需要中止时返回「准备」，点击「停止训练」，等待任务状态更新。再次启动前，确认已保存的检查点可用。

## 任务管理

### 任务名称自动生成

默认名称由训练类型和本机时间组成，例如 `sft_20261109_143052`。建议用名称区分不同数据或参数方案。

### 任务列表操作

- **新任务**：配置一项新的训练。
- **已有任务**：加载该任务的参数及状态。
- **删除任务**：点击非运行中任务旁的删除图标，确认后删除任务记录、训练日志和检查点记录。此操作不能在界面撤销；它不会替你清理磁盘上的模型输出文件。

运行中的任务必须先停止，才能删除。

### 任务状态

列表区分等待中、运行中、已完成、已停止和失败/错误。遇到失败时，先查看错误信息，不要只根据进度百分比判断训练是否成功。

## 参数模板

### 系统预设模板

SFT 模板默认启用 LoRA；预训练模板不使用 LoRA。模板是起点，并不保证适合所有模型或硬件。

### 自定义模板

1. 打开「训练参数配置」，选择模板并修改参数。
2. 点击模板选择框旁的保存图标，填写不重复的模板名称、训练类型和可选说明，确认保存。
3. 下次从模板列表选择即可复用。非默认模板可在抽屉的模板列表中点击删除图标并确认删除。

### 临时参数

修改参数后点击「应用」，可将这些值用于当前任务；不会覆盖原模板。页面会显示「临时配置」。关闭或取消抽屉，不应用本次尚未确认的修改。需要复用时，另存为自定义模板。

## 参数配置

参数按数据、训练、LoRA、优化、日志和通用配置分组。部分参数位于「可选参数」「高级参数」「保存参数」等折叠区域；显示内容取决于所选模板。

下面说明主要用途。默认值和可选范围以当前模板和界面显示为准，不要将某个模板的数值当成硬件要求。

## 数据配置参数

### 训练数据文件路径 / Training data file path

优先选择[数据处理](../dataset/sft.md)生成的 `train/final_dataset.jsonl`；训练中评估选择对应的 `eval/final_dataset.jsonl`。它们位于处理结果的 `final` 目录下，实际位置以输出清单为准。不要将 `data.jsonl` 和 `final_dataset.jsonl` 混为一谈：前者保留原始样本，后者是已分词的训练文件。

已有的训练专用 `.jsonl`、`.npy` 和 `.mmap` 文件也可使用，但须与模型分词器匹配。使用 `.mmap` 时保留同目录的配套文件。

SFT 也可使用每行一个 JSON 对象、包含 `messages` 数组的 JSONL，例如：

```json
{"messages":[{"role":"user","content":"你好"},{"role":"assistant","content":"你好！"}]}
```

原始 TXT、普通 JSON 数组、只有 `text` 字段的预训练语料，以及 DPO 问答对，不能直接当作本页的训练专用文件。预训练语料应先完成分词和训练格式导出；不能只修改扩展名。

### 评估数据文件

在「评估数据文件路径」选择独立的评估文件，并在训练配置中开启评估策略。文件应与训练文件使用匹配的格式和分词器。

**评估集采样比例**只控制从已提供的评估文件中取多少样本，不会从训练数据中自动划分评估集。对 JSONL/NPY 文件，设为 `0` 或 `1` 使用全部评估样本，`0` 与 `1` 之间的值使用相应比例。

### 其他数据参数

| 参数 | 用途与注意事项 |
|------|----------------|
| 训练模型目录 | 完整的本地基础模型目录，不是单个 GGUF 文件 |
| 训练输出目录 | 保存训练结果及检查点；建议不同实验使用不同目录 |
| 分词器路径 | 可选；留空时使用模型目录的分词器 |
| 恢复训练检查点路径 | 用于恢复已保存的训练状态，见[断点续训](#断点续训) |
| 加载现有 LoRA 权重继续训练 | 不等同于完整状态续训，首次训练保持关闭 |
| 最大样本数 | 限制用于训练的样本数量；`0` 表示不限制 |
| 是否重新打乱数据 | 影响样本顺序；对比实验时保持一致 |
| 数据加载器线程数 | 数据加载并行度；增加数值也会增加资源占用 |
| 是否使用锁页内存 | 数据加载选项，按运行设备和内存情况调整 |

## 训练配置参数

| 参数 | 用途 |
|------|------|
| 批次大小 | 每次处理的样本数；显存不足时可先降低 |
| 梯度累积步数 | 累积多个批次后再更新参数 |
| 最大序列长度 | 控制每个训练样本处理的 token 长度；长序列需要更多资源 |
| 学习率 | 控制每次参数更新的幅度 |
| 优化器、学习率调度器 | 控制更新方法和学习率变化；部分选项需要额外依赖或硬件支持 |
| 训练轮数 | 完整遍历数据的次数 |
| 最大训练步数 | 正值限制更新步数；`-1` 不设置此上限，仍受训练轮数限制 |
| 权重衰减、最大梯度范数 | 用于约束参数更新 |
| 预热比例、预热步数 | 控制训练开始时的学习率预热 |
| 学习率余弦退火周期 | 配合相应学习率调度器使用 |

### 保存和训练中评估

- **保存策略**：`steps` 按步数保存，`epoch` 按轮数保存，`no` 不定期保存。按步数保存时设置「保存步数」。
- **最大保存检查点**：限制保留数量，旧检查点可能被清理。需要保留特定检查点时，先另行备份。
- **评估策略**：默认 `no`；选择 `steps` 或 `epoch` 后，还需要有效的评估文件。按步数评估时设置「评估步数」。
- **早停步数**：界面中的这个名称表示连续多少次评估没有改善后停止，并非训练步数。`0` 禁用早停。开启时需要评估数据和有效评估策略；保存与评估策略应匹配，按步数保存时应使保存步数为评估步数的整数倍。
- **早停阈值**：改善幅度小于此值时，视为没有改善。

监控页的「评估损失」来自这里的训练中评估，与[评估页](./evaluate.md)的基准测试是不同操作。

## LoRA 配置参数

LoRA 只训练一组较小的附加权重，通常比更新全部模型参数节省资源。SFT 模板提供以下选项：

| 参数 | 用途 |
|------|------|
| 使用 LoRA 微调 | 开启 LoRA；关闭后训练方式和资源需求会改变 |
| LoRA 的 r 参数 | 控制附加权重的规模 |
| LoRA 的 alpha 参数 | 控制 LoRA 更新的缩放 |
| LoRA 的 dropout | 训练时的随机丢弃比例 |
| LoRA 目标模块 | 必须与模型实际层名称匹配，不同模型不一定使用相同名称 |
| 训练后合并 LoRA 权重 | 将训练后的 LoRA 与基础模型合并，会增加保存所需空间 |
| PEFT 配置路径 | 可选的已有 LoRA 配置；仅在明确需要时设置 |

保留原始基础模型。测试和评估未合并的 LoRA 检查点时仍需要它。

## 优化配置参数

- **QLoRA、8-bit 优化器**：依赖相应的 NVIDIA CUDA 环境和组件，不要仅因显存不足就直接开启。
- **FP16、BF16 混合精度**：按设备支持情况选择，不要同时开启。CPU 训练不使用 FP16。
- **TF32**：用于支持此格式的 NVIDIA GPU。
- **梯度检查点**：通过额外计算减少训练时的内存占用，可能降低速度。
- **低 CPU 内存使用**：减少模型加载阶段的 CPU 内存需求，不代表模型训练无需足够内存。

## 日志配置参数

「日志级别」控制日志详细程度。「日志记录步数」控制每隔多少步记录训练指标，预设值为 `10`。减小间隔可看到更密集的曲线，但日志量也会增加。

## 通用配置参数

「随机种子」用于控制随机过程。对比实验时保持种子、数据和参数一致；不同设备或运行环境下，不保证结果逐字或数值完全相同。
