## 环境要求

**本功能需在设置中安装额外的CPU或GPU环境依赖。**
- 进入 ModxAI Studio 的**设置**页面
- 在**系统**分类的环境配置区域，选择并安装所需的环境（CPU/GPU）

## 功能概述

选择数据类型后，按步骤转换、清理并导出数据。需要时，可启用 AI 合成或质量过滤；SFT 或 RAG 处理中断后可从指定步骤继续。

## 数据集类型

### SFT 数据集

用于生成监督微调训练数据，支持三种源数据类型：

**文本数据集**：
- 支持格式：PDF、Word（.doc/.docx）、PowerPoint（.ppt/.pptx）、Excel（.xls/.xlsx）、HTML、文本文件（.txt/.md/.csv/.json/.xml）、ZIP 压缩包
- 输出格式：标准化的 JSONL 训练数据

**代码数据集**：
- 支持格式：C/C++（.c/.cpp/.cc/.h/.hpp）、Shader（.hlsl/.glsl/.cg/.ush/.usf）
- 输出格式：结构化的代码训练数据

**结构化数据集**（文件类型选择「JSON」）：
- 支持格式：JSON、JSONL
- 按训练格式映射字段：SFT 使用指令、输入和输出；预训练使用正文；DPO 使用提示词、正向回复和拒绝回复。具体字段及示例见 [SFT 数据处理](./sft.md)
- 输出格式：标准化的 JSONL。导出格式可以是 SFT（`sft_chatml`）、预训练（`pretrain`）或 DPO（`dpo`）。字段如何映射见 [SFT 数据处理](./sft.md)

### RAG 数据集

用于生成检索增强所需的向量化知识库：

- 支持格式：与文本数据集相同（含结构化 JSON/JSONL）
- 输出格式：向量嵌入数据，存储于向量数据库

### 音频转文本

将音频文件转录为结构化文本：

- 支持格式：MP3、WAV、M4A、WMA
- 输出格式：JSON、SRT 字幕、HTML、Markdown

## 处理流程

### SFT 文本/代码处理步骤

下表用于非结构化文本和代码。结构化 JSON 训练数据只执行步骤 0 和 10。

| 步骤 | 名称 | 说明 | 必选 |
|------|------|------|------|
| 0 | 转换 | 解析输入文件，转换为统一格式 | ✓ |
| 1 | 清洗 | 清洗和预处理数据 | ✓ |
| 2 | 拆分 | 拆分超长数据块 | ✓ |
| 3 | 分析 | 质量分析和复杂度评估 | ✓ |
| 4 | AI 合成 | 使用 AI 模型合成增强数据 | 可选 |
| 5 | AI 合成解析 | 解析 AI 生成的数据 | 可选 |
| 7 | 整合 | 整合所有处理后的数据 | ✓ |
| 8 | AI 过滤 | 使用 AI 进行质量评估过滤 | 可选 |
| 9 | AI 过滤解析 | 解析过滤结果 | 可选 |
| 10 | 输出 | 输出最终训练数据 | ✓ |

### RAG 处理步骤

| 步骤 | 名称 | 说明 | 必选 |
|------|------|------|------|
| 0 | 转换 | 解析输入文件 | ✓ |
| 1 | 清洗 | 清洗和预处理 | ✓ |
| 2 | 拆分 | 拆分数据块 | ✓ |
| 3 | 分析 | 质量分析 | ✓ |
| 4 | AI 合成 | 使用聊天模型为文本块生成摘要 | 可选 |
| 5 | AI 解析 | 解析生成的摘要 | 可选 |
| 11 | 生成向量 | 使用向量模型生成嵌入 | ✓ |
| 12 | 存储向量 | 将向量存入知识库 | ✓ |

### 音频转文本处理步骤

| 步骤 | 名称 | 说明 | 必选 |
|------|------|------|------|
| 0 | 模型加载 | 加载音频转文本模型 | ✓ |
| 1 | 转录 | 将音频转录为文本 | ✓ |
| 2 | 输出 | 输出格式化的文本数据 | ✓ |

### 工作流模板

系统预置了多个工作流模板，可快速选择常用的步骤组合：

- **AI 合成**：包含 AI 合成步骤，适合需要扩充数据的场景
- **AI 质量**：包含 AI 合成和 AI 过滤步骤，适合追求高质量数据
- **自定义**：手动选择需要执行的步骤

> 非结构化文本和代码可在步骤 4（AI 合成）中将**导出格式**设为 `pretrain`；结构化 JSON 在页面上选择对应的**训练格式**。

## 输出目录与文件

### SFT 数据集输出

文本数据通常输出到「输出目录/datasets/text_dataset/final」。C/C++ 使用「datasets/code_dataset/final」，Shader 使用「datasets/shader_dataset/final」。已有任务可能使用既有目录布局，以进度提示和输出清单为准。

SFT 和预训练的输出示例：

```text
final/
├── training_dataset_manifest.json
├── training_validation.jsonl     # 有校验报告时生成
├── training_metadata.jsonl       # 有附加元数据时生成
├── train/
│   ├── data.jsonl
│   └── final_dataset.jsonl
├── eval/
│   ├── data.jsonl
│   └── final_dataset.jsonl
└── test/
    ├── data.jsonl
    └── final_dataset.jsonl
```

只输出非空分组。`data.jsonl` 保留标准化原始样本，`final_dataset.jsonl` 是已分词的训练文件。当前步骤 10 固定输出 JSONL，不提供 JSON/NPY 保存格式选择。

训练时选择 `train/final_dataset.jsonl`；训练中评估选择 `eval/final_dataset.jsonl`，并启用评估策略。预训练的 `data.jsonl` 不能直接代替训练文件。

DPO 每个非空分组只输出 `data.jsonl`，内容为提示词、正向回复和拒绝回复。当前训练模块不支持 DPO 训练。

### 输出文件命名

步骤 10 的 `training_dataset_manifest.json` 列出数据格式、划分、数量、校验汇总和实际产物路径。处理完成后先检查清单，再使用对应的训练文件。

各步骤可能有多个中间文件，不要把 `opt{N}_dataset.jsonl` 当作所有步骤唯一的文件名。详细字段和文件用途见 [SFT 数据处理](./sft.md#输出格式)。

### 输出格式选择

结构化 JSON 在页面上选择「训练格式」；非结构化文本和代码按所选处理步骤配置导出格式。支持 SFT、预训练和 DPO 样本，文件用途及当前训练支持范围见 [SFT 数据处理](./sft.md)。

## AI 节点特性

### 模型要求

使用 AI 节点（步骤编号 4、8）需要确保：

1. **模型库中有可用的聊天模型**：AI 节点使用聊天模型进行数据合成和过滤
2. **在步骤参数中选择模型**：点击步骤的设置按钮，选择要使用的 AI 模型

### 处理特性
1. 稳定高效的处理**大规模数据**
2. **进度跟踪与恢复**
3. **异常数据块自动修复**,重新启动后首先尝试自动修复异常数据块
4. **增量处理** 避免重复处理已完成的数据
5. **模型状态监控**, 发现异常自动重启模型以及超时重试机制

### 模型复用机制

本地 AI 节点在配置匹配时，可复用已加载的 llama.cpp 聊天模型。

- 复用条件包括基础模型、LoRA、上下文和运行参数，不只是模型名称相同。
- 数据处理步骤结束时不会主动卸载共享模型。
- 数据处理与聊天共享计算资源，聊天可能需要等待，响应速度也可能下降。
- 模型正被其他任务使用时，切换到不同配置可能被拒绝；请先等待相关任务结束。

### RAG 向量模型

RAG 数据处理的步骤编号 11（生成向量）需要：

1. **模型库中有向量模型（Embedding）**
2. **在设置中安装环境**：向量模型需要 CPU 或 GPU 环境支持
3. 在步骤参数中选择向量模型

## 断点续跑

本节适用于 SFT 和 RAG 的文本、代码处理流程。音频转文本不能从中断点继续；重新开始会从头转录，并可能覆盖已有的同名结果，详见[音频转文本](./audio2text.md)。

### 使用场景

- 某个步骤执行失败后，可从失败的步骤重新开始
- 修改某个步骤的参数后，只需重新执行该步骤及后续步骤
- 中断处理后，可从上次停止的位置继续

### 操作方法

1. **取消勾选已完成的步骤**：在步骤选择区域，取消勾选不需要重新执行的步骤
2. **保留需要执行的步骤**：勾选需要重新开始的步骤及其后续步骤
3. **点击开始处理**：系统将从第一个勾选的步骤开始执行

### 注意事项

- 确保前置步骤的输出数据存在且有效
- 如果修改了前置步骤的参数，建议重新执行该步骤
- 步骤之间存在数据依赖，跳过中间步骤可能导致数据不完整

## 注意事项

### 环境要求

| 功能 | 环境要求 |
|------|---------|
| SFT 文本处理 | 无需在**设置**中安装环境（基础步骤）|
| SFT 代码处理 | 需在**设置**中安装环境（解析步骤依赖 libclang）|
| SFT AI 节点 | 需要聊天模型已导入 |
| RAG AI 节点 | 需要聊天模型已导入 |
| RAG 向量生成 | 需要向量模型已导入，需要在**设置**中安装环境 + 向量模型 |
| 音频转文本 | 需要在**设置**中安装环境 (推荐 GPU 环境) |

### 常见问题

**Q：处理过程中可以切换到其他页面吗？**

A：可以。处理任务在后台运行，切换页面不影响处理进度。返回数据处理页面时可查看最新状态。

**Q：如何查看处理日志？**

A：切换到"进度监控"标签页，可查看实时处理日志。支持按日志级别（INFO/WARNING/ERROR）过滤显示。

**Q：AI 节点处理很慢怎么办？**

A：AI 节点需要调用 AI 模型进行推理，处理速度取决于模型大小和硬件配置。建议：
- 使用较小的模型进行快速处理
- 确保 GPU 可用以加速推理
- 减少待处理数据量进行测试
