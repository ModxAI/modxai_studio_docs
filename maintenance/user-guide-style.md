# 用户指南维护规范

本规范供维护者使用，不加入用户文档目录。

## 发布依据

- 已公开指南的历史基线为 **Windows 版 1.1.10**。本轮整理 **1.1.11 候选文档**，最终发布提交、安装包和支持平台尚待维护者确认；不得沿用旧版平台范围推断新版，也不得把版本号视为已发布证据。
- 本轮已核查并更新的页面使用 `v1.1.11 / 2026-11`；未核查页面不批量改版本。合并、发布前按最终交付版本复核。
- 只写有当前候选实现依据的功能和操作。其他平台、实验分支及未完成模块不能作为已发布能力写入指南。
- 功能、按钮、路径和限制须有对应正式版本的依据。无法确认时，不新增能力承诺，也不凭猜测替换现有操作步骤；在审阅说明中列出待核实问题。
- 用户指南不包含修复历史、内部组件升级记录、源码路径、开发任务编号或私有仓库链接。

## 页面顺序

1. **能做什么**：一两句话说明用途。
2. **使用前准备**：仅列完成操作必需的模型、文件、环境和权限。
3. **操作步骤**：从界面入口开始，按顺序写点击、选择、填写、确认。
4. **确认结果**：说明用户能看到的状态或输出，不保证模型回答正确。
5. **注意事项**：就近说明费用、联网、权限、不可逆操作、资源要求和真实限制。
6. **相关操作**：只链接有帮助的后续页面。

长参数表放在最小操作流程之后。保留仍被引用的标题和锚点；若必须修改，同步检查引用。

## 用词

- 优先写用户能执行的动作。按钮和字段名称与界面一致。
- 必要专业名词首次出现时简短解释；不要解释后台进程、缓存、适配器或字段传递。
- 分开写硬性要求、建议和可能影响效果的因素。不要把模型大小、量化格式或上下文建议写成未经证实的使用门槛。
- 避免“保证”“完全安全”“无需任何配置”“必定成功”等绝对承诺。README 同样使用具体功能和操作入口，不写口号、优越性比较或重复的优势列表。
- 保留必要限制和安全提醒，但不把开发进度、未完成事项或修复过程放入普通用户页面。
- 中英文同步操作、限制和版本信息；翻译保持自然，不逐字套用句式。

## 正反示例

| 不推荐 | 推荐 |
|---|---|
| 启动子进程并注册适配器 | 点击「启动连接」，等待状态显示「已连接」 |
| 管理员认证为进程内缓存 | 重启连接服务后，需要重新输入管理员密码 |
| 后端读取临时参数，与模板无关 | 本次修改只用于当前任务，不覆盖已保存的模板 |
| 已修复共用知识库时无法检索的问题 | 对话和智能体可以选择同一份已保存的知识库 |
| 4B 以下无法使用 | 按任务和可用资源选择模型，先用简单任务确认效果 |

## 交付检查

- 在独立分支修订，提交 draft PR；不直接修改 main、合并或发布。
- 候选稿记录核查的准确提交和范围；最终交付前对照实际发布版本核实新增事实，保留未核实项供维护者判断。
- 检查中英文对应、目录、链接、图片、锚点和 Markdown 格式。删除过时说明时，搜索两种语言的相关表述；重点对照账号与费用、步骤编号、环境要求、模型格式及可选条件，避免另一语言或 FAQ 继续保留旧说明。
- 操作指南不承担更新日志职责；修复说明放在单独的更新日志维护流程中。
- PR 说明真实检查范围。静态检查通过不等于产品功能已经实测。
- 公开 PR 不包含私有实现、日志、凭据或未公开路线。
